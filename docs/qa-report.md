## Звірка з Figma

Перевірено секції, фотографії, кадрування, розміри карток, шрифти й відступи.
Підсумкова висота початкової сторінки збігається з контрольними фреймами:

| Ширина  | Висота сторінки | Фрейм Figma |
| ------- | --------------- | ----------- |
| 375 px  | 7302 px         | `15337:9`   |
| 768 px  | 7795 px         | `15337:8`   |
| 1280 px | 5521 px         | `15307:32`  |

Це перевірка геометрії та візуальне порівняння, а не твердження про повний
піксельний збіг. Погоджені відмінності від макета:

- Catalog і Reviews мають шеврони для доступу до всіх карток.
- Catalog має Show less поряд із погодженою поведінкою Show more.
- Sale має п'ять мініатюр, перша — початкове велике фото; видно чотири. Шеврони
  циклічні, повторне натискання активної мініатюри повертає початкове фото.
- Sale і Reviews підтримують горизонтальний свайп на телефоні й планшеті.
- Contact Us перевіряє дані, очищує коректно заповнену форму й повідомляє, що
  надсилання не підключене.
- За окремою вказівкою користувача підсилено контраст текстів.

Повний мобільний фрейм Figma не повернув контекст через таймаут; звірку виконано
за контекстом мобільної Hero, даними секцій із попередніх етапів та геометрією
фрейма. Desktop і tablet повернули повний контекст.

## Інтерактивність і доступність

Перевірки виконані автоматично в Chromium через Playwright.

- Ширини: 320, 374, 375, 480, 767, 768, 1024, 1279, 1280, 1440, 1920 px, кожна
  зі щільністю 1 і 2.
- Меню: відкривання, Escape, перехід до секції, Tab/Shift+Tab у межах діалогу,
  повернення фокуса. Сценарії затемнення та зміни ширини також перевірялися під
  час реалізації меню.
- Catalog: перші чотири картки на телефоні, доступ до кінця списку, Show
  more/Show less, неактивні кнопки на межах, фокус після згортання.
- Sale: усі п'ять ракурсів, чотири видимі мініатюри, повернення початкового
  фото, перемикання адаптивних зображень і touch-жести.
- Reviews: кількість карток за шириною, перехід до останнього відгуку, клавіші
  ←/→, справжні touch-події Chromium, межі списку, короткі, вертикальні та
  скасовані жести.
- Contact Us: порожні поля, ім'я з пробілів, некоректний email, українські й
  нідерландські номери, фокус на помилці, очищення коректно заповненої форми,
  скидання помилок, повідомлення. Дані не передаються мережею.
- Footer: переходи, синхронізація активної секції, телефон, соціальні адреси,
  робота без JavaScript та довші нідерландські тексти.
- axe-core перевірено також із відкритим меню, усіма відкритими товарами,
  останнім відгуком, помилками форми та повідомленням після очищення.

Для контрасту введені токени `--color-text-secondary` і
`--color-on-accent-muted`. Темнішими стали ціни Catalog і тексти Reviews;
світлішими — артикул, попередня ціна й опис Sale. У copyright прибрано додаткове
зниження непрозорості. Розміри й компонування не змінені.

Автоматичний axe-аудит не підтверджує повну відповідність усім критеріям WCAG.
На фізичних телефонах, у Safari/Firefox та зі скринрідером перевірку в цьому
етапі не виконано. Вбудований браузерний перекладач не запускався; перевірено
дозвіл перекладу HTML та стійкість блоків до довших текстів.

## Збірка й GitHub Pages

- Vite оновлено з 5.4.21 до 7.3.7 через виявлені вразливості інструментів
  розробки. Плагіни й production-збірка перевірені після оновлення.
- Пакет `glob` видалено; пошук HTML використовує вбудований `node:fs.globSync`.
  Вимогу Node.js 24 додано в `engines`, `.nvmrc` та workflow уже містять 24.
- Додано команду `npm run check`; GitHub Actions виконує її після `npm ci`. У
  разі помилки форматування або збірки публікація не запускається.
- Теги `actions/checkout@v7`, `actions/setup-node@v7` та
  `JamesIves/github-pages-deploy-action@v4` існують у відповідних репозиторіях.
- Збережено base `/Watch_Charm/`, локальний preview перевірено саме за ним.
- Додано description сторінки. Favicon проєкту підключений локально.

Оновлення Vite звірене з офіційними настановами переходу
[з Vite 5](https://v6.vite.dev/guide/migration) та
[з Vite 6](https://v7.vite.dev/guide/migration).

Workflow на GitHub у цьому етапі не запускався: користувач самостійно робить
commit і push. Після push слід перевірити успішне виконання Actions і сайт на
GitHub Pages. Режим Pages: Deploy from a branch → gh-pages → /(root).

## Додаткове уточнення: закріплений Header

За запитом користувача Header залишається вгорі при прокручуванні, а контент
проходить під його непрозорим фоном. `scroll-padding-top` враховує висоту Header
при переходах до секцій; ResizeObserver оновлює її після зміни розміру або
перекладу текстів. CSS містить відступи для роботи без JavaScript.

Перевірено прокручування до середини й кінця сторінки, переходи до секцій, бічне
меню та зміну висоти Header на ширинах 320, 375, 768, 1024, 1280 і 1440 px.
Форматування й production-збірка успішні.

## Додаткове уточнення: індикатор секції при прокручуванні

Модуль `src/js/navigation.js` позначає поточну секцію через
`aria-current="location"` у Header, бічному меню та Footer. Наявний синій кружок
Header оновлюється при прокручуванні в обидва боки й після переходів за
посиланнями. Враховується фактична висота закріпленого Header; після зміни
розмірів секцій або вікна стан перераховується.

На Hero активний Home, на рекламному банері залишається Catalog, унизу сторінки
— Contact Us. Відкривання меню не змінює індикатор поточної секції. Ручне
прокручування не змінює URL й не додає записів до історії браузера.

Перевірено ширини 320, 375, 768, 1024, 1280 і 1440 px: прокручування вниз і
вгору, натискання пунктів, синхронізацію трьох навігацій, відкривання й
закривання меню, пряме посилання на Sale, повернення браузером та високий
viewport. Після повернення індикатор відповідає фактично видимій секції.

## Повторення основних перевірок

```sh
npm ci
npm run check
npm audit
npm run preview
```

Після запуску preview відкрити `http://localhost:4173/Watch_Charm/`. Для
перевірки в браузері повторити сценарії меню, Catalog, Sale, Reviews та Contact
Us, наведені вище. У Windows PowerShell за потреби використовувати `npm.cmd`
замість `npm`. Перед `npm ci` завершити запущений dev-сервер: Windows може
блокувати заміну його виконуваних файлів.
